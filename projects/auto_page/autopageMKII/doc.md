# เอกสารอธิบายการทำงานของ `autopage_MKII_ver4_2_1LITE.py`

สคริปต์นี้คือแอปพลิเคชันที่มี Graphic User Interface (GUI) ที่ทำงานร่วมกับ Bot แบบกึ่งอัตโนมัติ (Semi-Auto / User-Assist) สำหรับช่วยปฏิบัติงานในระบบขายหน้าร้าน (POS - Point of Sale) ที่ชื่อว่า "SMCO" จุดประสงค์หลักคือเพื่อลดภาระงานซ้ำซ้อนให้พนักงาน ทำให้สามารถทำงานสองอย่างพร้อมกันได้ (Task Balancing) เช่น การให้บอทจัดการคีย์ข้อมูลในขณะที่พนักงานกำลังหยิบสินค้าตามออเดอร์, เขียนเลข Invoice หรือจด Tracking ลงจ่าหน้าพัสดุ โดยใช้ Selenium WebDriver เป็นตัวขับเคลื่อนเบราว์เซอร์

---

## สถาปัตยกรรมหลักของโปรแกรม (Core Architecture)

โปรแกรมแบ่งโครงสร้างหลักออกเป็น 3 ส่วน ได้แก่:

1. **ส่วนติดต่อผู้ใช้งาน (GUI / Frontend)**: ถูกเขียนด้วยไลบรารี `tkinter` และ `customtkinter` 
2. **ส่วนการจัดการข้อมูล (Data Processing)**: ใช้ไลบรารีอย่าง `pandas` สำหรับอ่านไฟล์ Excel (`.xlsx`) และจัดการโครงสร้างข้อมูลที่ซับซ้อน เช่น การแยกที่อยู่และชื่อของลูกค้า
3. **ส่วนการทำงานอัตโนมัติ (Bot / Backend Automation)**: ใช้ `selenium` ควบคุมเบราว์เซอร์ Google Chrome เพื่อทำงานซ้ำๆ (RPA) บนระบบเว็บไซต์ของ SMCO แทนมนุษย์

## คลาสสำคัญ (Main Classes) และหน้าที่

### 1. `MyApp` (ระบบจัดการส่วนหน้าและการตั้งค่า)
คลาสนี้ทำหน้าที่รันหน้าต่างแอปพลิเคชันหลักของโปรแกรม (GUI) 
- **การจัดการภาพรวม GUI**: การปรับขนาดหน้าต่างให้อัตโนมัติ (`adjust_scale`), การ Scroll ด้วยเมาส์, การสร้างช่องกรอกข้อมูล (Forms), และปุ่มเพื่อรับคำสั่งจากผู้ใช้งาน
- **การคลีนข้อมูลลูกค้า**: มีฟังก์ชันสำหรับนำข้อมูลที่อยู่ดิบมารวม พิมพ์ให้ถูกต้อง และตัดตัวหนังสือที่ซ้ำซ้อนทิ้ง เช่น `clean_address`, `clean_duplicate_parts`, `cus_tel_fixer`, และการแปลภาษาอำเภอ/จังหวัดผ่าน `translate_eng_to_thai_place`
- **รองรับโหมดสองแบบ**:
  - **โหมดปกติ (Normal Mode)**: กรอกข้อมูลออเดอร์ทีละรายการ
  - **โหมด Accel (Accel Mode)**: โหมดทำงานอัตโนมัติต่อเนื่อง (Batch processing) โดยอ่านไฟล์ Excel ทีละหลายรายการและให้บอททำงานเป็นคิว
- **การคำนวณราคา & ส่วนลด**: มีส่วนช่วยในการแยกข้อมูลค่าจัดส่ง (Shipping cost) และคูปองหรือส่วนลดต่างๆ จากผู้ขาย

### 2. `Bot_POS` (ระบบหุ่นยนต์อัตโนมัติ)
คลาสนี้เป็นส่วนสั่งการ Selenium WebDriver โดยมีกระบวนการทำงานหลักๆ ดังนี้:
- **เตรียมความพร้อมเบราว์เซอร์**: ควบคุมและเปิด Google Chrome จัดการเซสชันและเตรียมพร้อมรับคำสั่ง (`setup_chrome`, `reconnect_driver`)
- **กรอกข้อมูลลูกค้าลงเว็บ SMCO**: 
  - `addCustomer` / `customer_class_selector`: จัดการเรื่องการเพิ่มชื่อลูกค้าใหม่ ถ้าไม่มีในระบบจะทำการกรอกฟอร์มให้
  - `tax_address_corrector`: แกะและแก้ไขข้อมูลที่อยู่สำหรับการออกใบกำกับภาษีโดยเฉพาะ
- **การจัดการสินค้าและส่วนลด**: 
  - `smco_set_overcharge_product` / `smco_set_discount_product`: จัดการเพิ่มสินค้าราคาพิเศษ หรือการกรอกคูปองส่วนลดแบบพิเศษ (`cp_sonic_blow_process`)
  - ค้นหาสินค้าจากรหัส (SKU) และหยิบลงตะกร้าแบบอัตโนมัติ
- **การพิมพ์และจัดการเอกสาร (PDF)**:
  - ดึงข้อมูลใบกำกับภาษีออกมาในรูปแบบ PDF (ผ่าน Base64) แล้วสั่งพิมพ์ออกเครื่องปรินต์แบบเบื้องหลัง (Silent printing) ผ่าน `SumatraPDF` หรือ Windows API โดยไม่ต้องให้ผู้ใช้ออกแรงกด

### 3. คลาสเสริมอื่นๆ (Helpers)
- **`PopUp`**: สร้างหน้าต่างเด้งขึ้นมาเพื่อแจ้งเตือน (Alert) หรือให้ผู้ใช้กดยืนยัน
- **`UserAccount`**: เป็น Subwindow ภายใต้ `MyApp` เพื่อจัดการการล็อกอินและรับ User ID / Password ของผู้ใช้งานในแอป
- **`DataSourceSelector`**: หน้าต่างให้ผู้ใช้เลือกว่าจะดึงข้อมูลที่อยู่ลูกค้ามาจากที่ใด เช่น จากไฟล์ดิบ Excel ข้อมูลนำเข้า หรือผ่าน API

## ขั้นตอนการทำงานของโปรแกรม (Workflow)

1. **เริ่มต้นโปรแกรม (Initialization):**
   - รันซอฟต์แวร์ขึ้นมา โปรแกรมจะโหลดการตั้งค่าพื้นฐาน, คีย์ต่างๆ จากไฟล์ `.env`, และโหลดพจนานุกรมตำบลจากไฟล์ `Addresscleaner_TambonData.xlsx`
   - หน้าต่าง GUI จะปรับสเกลตามหน้าจอคอมพิวเตอร์ และแสดงปุ่ม/ช่องให้ตั้งค่าระบบ (เช่น กดเพื่อใส่ User/Password)
2. **การนำเข้าข้อมูล (Data Input):**
   - ผู้ใช้งานทำการอิมพอร์ต (Import) ไฟล์ Excel เข้ามาผ่านปุ่มบนหน้าจอ 
   - แอพจะทำการประมวลผล (Parsing) จัดเก็บเข้า `pandas` dataframe เตรียมความพร้อมไว้
3. **การประมวลผลและส่งให้ Bot (Execution / Operation Task Thread):**
   - เมื่อกด Start ระบบตะรับข้อมูล Customer Name, Tax ID, Address, สินค้า (SKU และจำนวน)
   - ฟังก์ชันที่รับหน้าที่คลีนทำความสะอาดที่อยู่ จะตัดซอยข้อมูลที่ยุ่งเหยิง จัด format เบอร์โทร
   - `Bot_POS` ซึ่งทำงานอยู่บนอีก Thread หนึ่ง (แยกการประมวลผลเพื่อให้หน้าจอ GUI ไม่ค้าง) จะยิงคำสั่งเปิดระบบ POS 
   - บอทจะทำการตรวจสอบ ชื่อลูกค้า → ใส่ที่อยู่ส่งสินค้า **ในขั้นตอนนี้ระบบออกแบบมาในลักษณะ Semi-auto (User-Assist)** โดยกระบวนการบางอย่างจะมีการใช้ `while loop` เพื่อหยุดรอรับการกระทำจากฝั่งผู้ใช้งาน เช่น
     - **รอการยิงบาร์โค้ด**: ผู้ใช้สามารถใช้ Barcode Reader ยิงสแกนสินค้าจริงที่หยิบมาจากคลัง เพื่อใส่รหัส SKU ข้ามไปที่ฝั่งโปรแกรม
     - **รอการปรับแต่งราคาและคูปอง**: ระหว่างที่บอทรอ ผู้ใช้สามารถพิจารณาปรับลดราคา หรือเลือกกดใช้คูปองให้ตรงกับต้นทุนฝั่ง Production ที่กำหนดไว้ได้ด้วยตนเอง
   - เมื่อข้อมูลครบถ้วน บอทหรือผู้ใช้จะกดจบออเดอร์ (Finish Order / f2)
4. **กระบวนการพิมพ์เอกสาร (Print Handling):**
   - เมื่อสร้างออเดอร์เสร็จ บอทจะใช้ฟังก์ชันดึงภาพหน้าจอใบสั่งซื้อหรือ PDF
   - ส่งตรงไปที่คิวเครื่องปรินต์ (หรือเซฟไว้) แบบเงียบๆ เพื่อความรวดเร็ว

## สรุป
ระบบ `autopage_MKII_ver4_2_1LITE.py` ถูกสร้างขึ้นมาในฐานะ **ผู้ช่วยกึ่งอัตโนมัติ (User-Assist Agent)** เพื่อลดภาระงาน Data Entry ซ้ำซ้อนของพนักงานขาย/แอดมิน ที่ต้องคอยนำข้อมูลการสั่งซื้อจาก Marketplace ต่างๆ มาคีย์ซ้ำลงในระบบ SMCO POS ของทางร้าน โดยระบบนี้ไม่ได้ทำงานข้ามขั้นตอนทั้งหมดโดยพลการ แต่ถูกตั้งใจให้มีจังหวะ "หยุดรอ" ผู้ใช้งาน เพื่อให้พนักงานสามารถทำงานคู่ขนานกันไปได้ระหว่างงานเอกสารออนไลน์ (ระบบจัดให้) และงานออฟไลน์ (พนักงานหยิบแพ็กของ, กรอกข้อมูล Tracking หน้ากล่อง) ครบสูตรการทำ Multi-tasking อย่างมีประสิทธิภาพ
